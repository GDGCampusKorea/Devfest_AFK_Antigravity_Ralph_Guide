# 20분 중간 점검 & 트러블슈팅 가이드

`ralph.sh`를 실행해 두고 자리를 비운 뒤(AFK), **20분마다** 돌아와 아래 순서대로 상태를 점검하세요.
루프가 정체(`🛑 연속 N회 진전이 없어 중단`)되었거나 커밋 누락으로 중단되었을 때도 이 문서의 순서대로 조치하면 안전하게 복구할 수 있습니다.

---

## 1. 20분 체크포인트 4줄 확인

터미널에서 아래 4개 명령을 순서대로 실행합니다.

```bash
# 1) 최근 커밋이 태스크별로 깔끔하게 쌓이고 있는지 확인
git log --oneline -5

# 2) 커밋되지 않고 남아 있는 변경 파일이 있는지 확인
git status

# 3) 완료/차단 기록 확인 (BLOCKED 줄이 있는지 확인)
tail -n 20 progress.txt

# 4) 가장 최근 로그의 마지막 50줄 확인
tail -n 50 "$(ls -t logs/ralph-*.log | head -1)"
```

### 정상 진행 시 출력 예시
```text
$ git log --oneline -5
8c1a2f0 feat: task 2 — create project skeleton
3b9d4e1 feat: task 1 — add TEAM.md
1a0f9c2 docs: fill PRD for AFKathon

$ git status
On branch main
nothing to commit, working tree clean

$ tail -n 20 progress.txt
TASK 1 DONE — Created TEAM.md matching PRD
TASK 2 DONE — Created project skeleton and verified entry script
```

그다음 **검증 담당자**가 결과물을 직접 실행해 봅니다 (예: 웹 페이지 열기, CLI 명령 실행, 테스트 스크립트 실행).

## 2. PRD 체크(`[x]`)와 Git 커밋이 어긋난 경우

`ralph.sh`는 커밋이 누락되거나 작업 트리가 깨끗하지 않으면 작업 내용을 보존한 채 즉시 중단합니다. 상황에 따라 아래처럼 맞춘 뒤 `bash ralph.sh`를 다시 실행하세요.

| 상황 | 확인 방법 | 해결 방법 |
|------|-----------|-----------|
| **Case A. PRD는 `[x]`인데 커밋이 없거나 일부 파일이 미커밋** | `git status`에 수정된 파일이 남아 있음 | 결과물이 `Done when`을 만족하면 직접 커밋:<br>`git add -A && git commit -m "feat: task <n> — <요약>"`<br>만족하지 못하면 아래 Case C로 이동 |
| **Case B. 커밋은 됐는데 PRD가 `[ ]` 그대로임** | `git log -1`에 태스크 커밋이 있으나 `PRD.md`는 `[ ]` | `PRD.md`에서 해당 태스크를 `[x]`로 바꾸고 `progress.txt`에 `TASK <n> DONE — <요약>`을 추가한 뒤 커밋 |
| **Case C. PRD는 `[x]`인데 실제 결과물이 미완성/오류** | 직접 실행 시 동작하지 않거나 `Done when` 불충족 | `PRD.md`에서 `[x]`를 다시 `[ ]`로 되돌리고 커밋한 뒤, 아래 **3장(정체 시 대응 순서)**에 따라 태스크를 수정 후 재실행 |

## 3. 정체(Stall) 시 대응 순서

`ralph.sh`가 `🛑 연속 2회 진전이 없어 중단합니다.`로 멈췄거나, 같은 태스크에서 타임아웃(`rc=3`)이 반복된다면 **반드시 아래 순서대로** 조치하세요.

### 1단계: 태스크 쪼개기 (`PRD.md` 수정)
정체의 가장 흔한 원인은 **태스크 1개가 한 번의 세션(10분 목표, 15분 타임아웃) 안에 끝내기엔 너무 크거나**, `Done when` 조건이 모호해서 에이전트가 검증을 통과하지 못하는 경우입니다.
- 막힌 태스크를 **2~3개의 더 작은 태스크**로 나눕니다.
- `Done when`을 에이전트가 직접 실행해서 통과 여부를 확인할 수 있는 **실행 가능한 명령과 기대 출력** 형태로 바꿉니다.

### 2단계: `AGENTS.md`에 금지/가이드 규칙 추가
로그(`logs/ralph-*.log`)나 `progress.txt`의 `BLOCKED` 사유를 보고, 에이전트가 **같은 실수를 반복**하고 있다면 프로젝트 루트에 `AGENTS.md`를 만들거나 규칙을 추가합니다. Antigravity는 매 세션 시작 시 `AGENTS.md`를 자동으로 읽습니다.

```markdown
# AGENTS.md
- 외부 패키지를 임의로 설치하지 마세요.
- 기존 설정 파일의 키 이름을 바꾸지 마세요.
- 테스트 서버를 백그라운드로 띄운 채 종료하지 마세요.
```

### 3단계: 롤백 (스냅샷 커밋 → 백업 브랜치 → reset)
에이전트가 코드를 크게 망가뜨려 이전 상태로 돌아가야 할 때, 커밋되지 않은 수정(방금 손으로 나눈 `PRD.md` 등)이 남아 있는 상태에서 바로 `git branch`와 `git reset --hard`를 실행하면 **커밋되지 않은 변경이 모두 사라집니다**. 반드시 아래 순서대로 진행하세요.

```bash
# 1) 실행 중인 ralph.sh가 있다면 Ctrl+C로 루프 중단 확인

# 2) 현재 작업 트리의 변경을 스냅샷으로 커밋 (미커밋 작업 보존)
git add -A
git commit -m "wip: backup before reset"

# 3) 현재 스냅샷을 가리키는 백업 브랜치 생성
git branch "backup/before-reset-$(date +%H%M)"

# 4) 커밋 목록에서 안전했던 마지막 커밋 해시 확인
git log --oneline -10

# 5) 해당 커밋으로 되돌리기 (예: a1b2c3d)
git reset --hard <안전한-커밋-해시>
```

> 백업 브랜치에서 방금 수정해 둔 `PRD.md` 등 **필요한 파일만** 꺼내오려면 브랜치를 통째로 옮기지 말고 아래 명령을 사용하세요:
> ```bash
> git checkout backup/before-reset-1420 -- PRD.md
> git add PRD.md && git commit -m "docs: restore refined PRD"
> ```

### 4단계: 재실행
작업 트리가 깨끗한지(`git status`) 확인한 뒤 다시 루프를 실행합니다. `ralph.sh`는 `PRD.md`에서 아직 `[ ]`로 남아 있는 가장 앞 번호 태스크부터 자동으로 이어서 진행합니다.

```bash
bash ralph.sh
```

## 4. 남은 시간에 맞춰 PRD 범위 줄이기 (Scope Cut)

해커톤에서는 **완벽하지만 미완성인 10개 기능**보다 **실제로 돌아가는 핵심 기능 1개**가 훨씬 중요합니다. 20분 점검 때마다 남은 시간을 보고 아래 기준으로 과감하게 `PRD.md`의 미완료 태스크를 줄이세요.

| 남은 시간 | 현재 상태 | 판단 기준 및 행동 |
|-----------|-----------|-------------------|
| **60분 이상** | 태스크가 순조롭게 진행 중 | 현재 `PRD.md` 유지. 막힌 태스크만 잘게 쪼개기 |
| **40~60분** | 핵심 기능(Task 2~3)이 아직 미완료 | 부가 기능/꾸미기 태스크를 줄이고 **핵심 기능 1개** 완성에 집중 |
| **20~40분** | 핵심 기능은 동작하나 다듬기 남음 | 새 기능 추가 중단. 오류 처리 1개 + `README.md` 작성만 남기고 `RALPH_MINUTES=20`으로 실행 |
| **20분 미만** | 데모 준비 필요 | `ralph.sh` 종료. 현재 동작하는 버전을 그대로 보존하고 데모 영상·1분 피칭 준비에 집중 |

> **포기할 태스크 처리 방법**: `ralph.sh`는 `PRD.md` 전체에서 `- [ ]` 줄을 찾으므로 섹션만 옮기면 여전히 미완료 태스크로 집계됩니다. 포기할 태스크는 **해당 줄을 삭제하거나, 체크박스(`- [ ] `)를 일반 글머리(`- `)로 바꾼 뒤** 커밋하세요.
